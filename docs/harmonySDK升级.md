# HarmonyOS 工程升级指南：API 12 升至 API 21

## 1. 升级背景与目标

- **当前版本**：SDK 5.0.0(12) —— 对应 HarmonyOS NEXT 早期版本。
- **目标版本**：SDK 6.0.1(21) —— 对应最新的 HarmonyOS 6.0 版本。
- **升级目标**：适配 HarmonyOS 最新系统特性，优化 ArkWeb、多线程及底层渲染性能；同时**保持对原有 API 12 老旧设备（HarmonyOS 5.0 用户）的向下兼容**。

---

## 2. 环境与工程配置升级

### 2.1 升级开发环境

1.  **下载最新 IDE**：团队所有开发人员需前往华为开发者联盟官网，下载并安装 **DevEco Studio 6.0.1 Release（或 Beta 版）**。
2.  **配置 SDK**：首次打开新版 IDE 时，根据向导自动下载并配置 OpenHarmony SDK `6.0.1.xxx`（API 21）。
3.  **注意**：建议开发人员保留原 DevEco Studio 5.0.0 的安装目录（或通过 Toolbox 多版本共存），以便在遇到重大编译阻碍时作为回滚备用。

### 2.2 修改 `build-profile.json5`

为了确保在最新系统上采用新行为，同时不抛弃老系统的用户，请严格按照以下配置修改：

**1. 工程级（根目录 `build-profile.json5`）**
将 `compileSdkVersion` 升至最新，以使用新版编译器和类库：

```json5
{
  app: {
    compileSdkVersion: "6.0.1(21)",
  },
}
```

**2. 模块级（如 `entry/build-profile.json5` 及所有依赖模块）**
修改 `targetSdkVersion` 为新版本，**严格保留 `compatibleSdkVersion` 为 12**：

```json5
"products":[
  {
    "name": "default",
    "signingConfig": "default",
    "compatibleSdkVersion": "5.0.0(12)", // 核心：保持12不变，决定了该包能否装在旧手机上
    "targetSdkVersion": "6.0.1(21)",     // 决定了应用在新手机上运行时，系统应用的新特性策略
    "runtimeOS": "HarmonyOS"
  }
]
```

## 3. 开发适配与核心注意事项 ⚠️

从 API 12 跨越到 API 21，底层框架、编译器和组件行为有较大变化，开发阶段需重点关注以下事项：

### 3.1 跨版本 API 调用的安全拦截（重中之重）

**风险项**：由于代码在 API 21 环境下编译，IDE 允许您调用 API 13~21 的新接口；但由于兼容版本仍是 API 12，这些新接口在旧手机上**完全不存在**，直接调用会导致应用 Crash。
**解决方案**：引入 API 13 及其以上的新特性时，**必须**使用 `canIUse` 进行环境嗅探。

```typescript
// 错误示例：直接调用 API 18/21 新增的方法（旧手机必崩）
// userAuth.doSomethingNew();

// 正确示例：先判断系统是否支持该能力
if (canIUse("SystemCapability.UserIAM.UserAuth.Core")) {
  // 调用 API 高版本的新特性
} else {
  // 降级处理，使用 API 12 的旧方案，或者提示用户升级
}
```

### 3.2 编译期语法与状态管理校验变严

新版 ArkTS 编译器具备更严格的静态类型检查：

- **状态管理严格化**：之前 `@State`、`@Prop` 中可能存在的一些不规范的直接赋值修改（如跨层级修改非响应式对象深层属性），在新编译器下可能会报错或失效，需修复为标准的 ArkUI 响应式更新方式。
- **类型安全**：`any` 类型的滥用以及联合类型未判断直接使用的场景，可能会产生大量编译 Warning 或 Error，需排查并清理。

### 3.3 ArkWeb (Web 组件) 内核与行为变更

Web 引擎底层内核（Chromium）从 API 12 到 21 进行了大版本升级（升级至 Chromium 132 等级）。

- **前端样式渲染**：部分非标准的 CSS 写法在新内核下可能表现不同。
- **交互行为**：输入法键盘弹起时的页面避让规则、H5 页面滚动穿透问题可能发生改变。
- **安全策略**：跨域请求（CORS）与 Cookie 校验更加严格，请确认 H5 页面请求是否正常。

### 3.4 ArkUI 视觉与渲染变更

- **SVG 图像解析**：API 21 对 `Image` 组件的 SVG 解析引擎做了重构。需全量检查 App 内的 SVG 图标是否存在拉伸、毛边、尺寸失常或颜色丢失现象。
- **动画过渡**：旧版系统部分冗余的动画执行在新版中可能会被优化，检查复杂动画（如 SharedTransition、自定义动画）的连贯性。

### 3.5 多线程并发机制 (TaskPool / Sendable)

如果您的工程中使用了 `TaskPool` 进行耗时任务处理：

- API 12 时期 `Sendable` 对象的规则相对粗糙。新版本对跨线程传递对象有更严格的校验要求。检查多线程间共享的自定义对象是否会触发序列化/反序列化异常。

## 4. 测试与回归验证清单 (QA 关注点)

测试团队应采用 **新设备（API 21 / HarmonyOS 6.x）** + **旧设备（API 12 / HarmonyOS 5.0 首发版）** 双路并发测试：

| 测试模块         | 重点验证内容                                                                            | 验证环境推荐 |
| :--------------- | :-------------------------------------------------------------------------------------- | :----------- |
| **安装与启动**   | 验证应用能否正常安装、启动，有无初始化 Crash（通常由误调用新 API 引起）。               | 新、老设备   |
| **前端 H5 页面** | H5 页面渲染是否正常；JS Bridge 与原生通信是否正常；输入框弹起是否遮挡。                 | 主要在新设备 |
| **UI 视觉排查**  | 全局巡查 SVG 图标是否清晰、尺寸正常；自定义弹窗、半屏模态面板显示是否正常。             | 主要在新设备 |
| **硬件与权限**   | 验证相机调用、相册选图、位置获取（核心验证 `startAbilityForResult` 结果回传是否成功）。 | 新、老设备   |
| **后台任务**     | 若有后台播放、后台定位、后台下载，将其放入后台静置 5-10 分钟，检查是否被系统强杀。      | 主要在新设备 |
| **三方 SDK**     | 检查接入的微信、支付宝、地图等闭源第三方 SDK 在新 SDK 下的兼容性。                      | 新、老设备   |

## 5. 升级演进与回滚策略

1.  **拉取分支**：务必在 Git 上新建独立的升级分支（例如：`feature/upgrade-api21`），不要在主干直接改动。
2.  **分阶段合并**：
    - **Phase 1**：仅升级开发环境和编译配置，处理掉所有的编译报错和 Warning，使其能成功 Build 并跑通基础功能。
    - **Phase 2**：对重点 API 进行 `canIUse` 改造。
    - **Phase 3**：QA 全量回归。
3.  **回滚方案**：如果发现重大且短时间无法解决的第三方依赖包兼容性问题（如底层 C++ 库在 API 21 崩溃），则废弃该分支，继续使用 API 12 的打包配置发布版本。
